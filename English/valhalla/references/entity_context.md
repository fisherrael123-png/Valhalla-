## 1. Core Definition

AGEA, or Agentic Graph Extraction Attack, is a query-efficient agentic graph-extraction method for GraphRAG systems. Under black-box access and a fixed query budget, it uses multi-turn adaptive queries to recover entities, relationships, and local structure from a hidden knowledge graph through GraphRAG's natural-language responses.

This entity does not describe one prompt or one experiment. It captures the paper's complete topic: graph-level extraction risks in GraphRAG, the AGEA framework, query strategy, extraction and filtering mechanisms, experimental validation, limitations, and defensive implications.

## 2. Problem Background

GraphRAG organizes a document collection as a graph of entities and relationships, retrieves a relevant subgraph for each user query, and generates an answer around that subgraph. Compared with ordinary RAG's retrieval of text chunks, GraphRAG exposes a more structured attack surface: through multiple queries, an attacker can traverse the graph, expand neighborhoods, and assemble relationship evidence to reconstruct reusable relational graph structure.

The critical risk is not merely the disclosure of source-text fragments, but disclosure of structured knowledge such as who is related to whom, how they are connected, and which nodes are central hubs. For medical, organizational, communication, or business knowledge graphs, such leakage can support later association inference and targeted analysis.

### Risk Differences Between GraphRAG and Ordinary RAG

| Comparison dimension | Ordinary RAG extraction risk | GraphRAG graph-level extraction risk |
|---|---|---|
| Primary asset | Text chunks, document fragments, retrieval context | Entities, relationships, subgraphs, graph structure |
| Unit of leakage | Sentence, paragraph, chunk, document | Node, edge, path, neighborhood, community |
| Attacker's gain | Partial source text or facts | A reusable, queryable structured knowledge graph |
| Multi-turn risk | Repeatedly retrieve more text chunks | Traverse the graph, expand neighborhoods, and recover the graph skeleton |
| Downstream harm | Content leakage, copyright, or privacy problems | Association inference, organizational reconstruction, and discovery of sensitive relationships |

## 3. Threat Model

The paper studies a budget-constrained black-box setting. The attacker cannot access GraphRAG's retriever, internal knowledge graph, retrieved subgraphs, or underlying model parameters. The attacker may only submit queries and observe the system's natural-language responses.

The objective is to recover the entity and relationship sets of GraphRAG's internal graph using as few queries as possible. The challenge is that response text may mix genuine retrieved content, model-generated background, and hallucinated relationships; the attacker cannot see the actual retrieved subgraph; and under a limited query budget, naive repeated queries waste resources in low-yield or saturated regions.

### Threat-Model Table

| Item | Setting |
|---|---|
| Attacker access | Interaction with GraphRAG only through the query interface |
| Hidden from attacker | Internal knowledge graph, retriever, retrieved subgraph, and underlying model parameters |
| Visible to attacker | Natural-language response to each user query |
| Attack objective | Recover the entity set, relationship set, and portions of graph structure |
| Budget constraint | Fixed number of queries; 1,000 queries in the main experiment |
| Evaluation target | Coverage and correctness of the extracted graph relative to the true internal graph |
| Main challenges | Response noise, hallucinated relationships, redundant queries, local saturation, and long-horizon planning |

## 4. Method Overview

AGEA models graph extraction as a closed-loop feedback process with four core components:

| Component | Description | Role in AGEA |
|---|---|---|
| Query Generator Q | Adaptive attack-query generator | Generates the next query from current graph state, query history, and novelty feedback |
| Graph Extraction-Filter Module F | Graph extraction-and-filtering module | Extracts candidate entities and relationships from responses, then filters generic items, duplicates, unsupported relationships, and hallucinated nodes |
| Graph Memory M_G | Graph memory | Maintains both the raw candidate graph and the filtered high-confidence graph |
| Query Memory M_Q | Query memory | Records historical queries, response summaries, extraction results, mode selections, and novelty trends |

AGEA's central idea is to separate “discovering more graph structure” from “maintaining extraction precision.” It first discovers candidate entities and relationships rapidly to compute novelty, then uses the filtering module to control noise, and finally writes trusted results into the filtered graph.

### Method Process

| Step | Input | Processing | Output |
|---:|---|---|---|
| 1 | Extracted graph, query memory, novelty trend | Select exploration or exploitation mode | Query mode |
| 2 | Query mode, filtered graph, recent history | Generate a natural-language query | Attack query |
| 3 | Attack query | Target GraphRAG retrieves a subgraph and generates an answer | Natural-language response |
| 4 | Response text | Discovery phase parses candidate entities and relationships | Updated raw candidate graph |
| 5 | Candidate entities and relationships, response evidence, filtered-graph context | Filtering phase validates and denoises | High-confidence entities and relationships |
| 6 | Raw graph, filtered graph, query memory | Compute novelty and update state | Basis for the next query |

## 5. Algorithmic Mechanisms

### 5.1 Two-Stage Graph-Knowledge Extraction

AGEA uses a two-stage extraction process. The first, discovery stage rapidly obtains candidate entities and relationships from a response so it can update the raw graph and compute novelty. The second, filtering stage removes generic entities, duplicate expressions, unsupported edges, and anomalously dense connections from the candidate results, writing only high-confidence entities and relationships to the final filtered graph.

| Stage | Objective | Method | Advantage | Risk or limitation |
|---|---|---|---|---|
| Discovery | Rapidly obtain candidate entities and relationships | Structured-output elicitation + rule-based parsing + normalization + deduplication | Low overhead; novelty can be calculated after every turn | May include generic items, hallucinated relationships, or formatting noise |
| Filtering | Preserve high-confidence graph structure | An LLM filtering agent evaluates response evidence together with graph memory | Improves precision and limits propagation of erroneous edges | Adds inference overhead and depends on model judgment quality |

### 5.2 Graph Memory

AGEA maintains two graph states simultaneously:

| Graph state | Content | Primary purpose |
|---|---|---|
| Raw graph G_r | Every candidate entity and relationship found during discovery | Compute novelty and determine whether the current queries still yield discoveries |
| Filtered graph G_f | High-confidence entities and relationships confirmed through filtering | Final evaluation, query planning, duplicate detection, and selection of high-value nodes for exploitation |

This dual-graph design prevents early filtering from underestimating novelty and prevents noise from being written directly into the final graph. The raw graph favors recall; the filtered graph favors precision. Together they improve query efficiency.

### 5.3 Query Memory

Query memory records recent queries, response summaries, extraction results, mode selections, and novelty trends. It helps avoid repeatedly exploring the same region and lets the query generator select more promising directions from historical feedback.

| Memory content | Purpose |
|---|---|
| Historical queries | Avoid repeating similar questions |
| Response summaries | Determine which topics have already been covered |
| Recently extracted entities | Avoid immediately re-exploring the same entities |
| Novelty scores | Determine whether the current region is saturated |
| Mode-selection record | Analyze imbalance between exploration and exploitation |
| Entity query frequency | Prevent excessive repeated queries around a single hub |

### 5.4 Novelty-Driven Exploration-Exploitation Strategy

AGEA switches between exploration and exploitation. Exploration discovers new entity types, relationship types, and graph regions. Exploitation expands local neighborhoods around high-value entities already discovered.

The paper interprets novelty as a “saturation signal.” Low recent novelty means current queries mostly repeat known nodes or edges and should shift toward exploration. High recent novelty means the current region still has extraction value and can be further exploited around known entities. The filtered graph also identifies highly connected entities, guiding exploitation toward nodes more likely to reveal new edges.

| Mode | Objective | Trigger tendency | Query characteristics | Potential problem |
|---|---|---|---|---|
| Explore | Discover new entities, relationship types, and graph regions | Low recent novelty or random exploration trigger | Broader topics, greater coverage, avoidance of recent entities | May have low hit rates and fail to develop deep relationships |
| Exploit | Expand neighborhoods around known entities | High recent novelty indicates the current region remains valuable | Focus on hubs or newly discovered entities and ask about direct relationships | May amplify local errors or become trapped in a local graph region |

### 5.5 Key Hyperparameters

| Parameter | Paper setting | Meaning |
|---|---:|---|
| Initial exploration probability ε_init | 0.3 | Maintains a relatively high exploration rate early in the attack |
| Minimum exploration probability ε_min | 0.05 | Retains a small amount of random exploration late in the attack |
| Exploration-probability decay | 0.98 / turn | Gradually shifts from exploration toward exploitation over query turns |
| Initial novelty threshold τ_init | 0.15 | Initial threshold for judging whether recent queries are saturated |
| Recent window k | 5 | Uses mean novelty over the last five turns to help select a mode |
| Main-experiment query budget | 1,000 | Budget for the Medical and Agriculture main experiments |

|---|---:|---:|---:|---:|
| TGTB | 34.85 | 22.61 | 60.06 | 53.29 |
| PIDE | 45.87 | 31.38 | 70.32 | 63.00 |
| AGEA | 60.71 | 52.57 | 80.93 | 73.98 |

Conclusion: On a larger, more diffuse graph such as Novel 20 books, AGEA's node and edge leakage rates decline but remain substantially higher than TGTB and PIDE. Its edge leakage is 52.57, compared with 31.38 for PIDE and 22.61 for TGTB, indicating that agentic query steering still improves relationship recovery on sparse, diverse, low-redundancy graphs.

## 11. Supplementary Experiment: Naive-RAG Control

The paper also conducts a supplementary experiment on an ordinary vector-retrieval Naive-RAG setting to distinguish the “GraphRAG structural retrieval surface” from the “ordinary text-retrieval surface.” After graph structure is removed, every method's edge-recovery ability drops substantially. AGEA-Naive still achieves the highest node and edge leakage, but with precision far below that in the main GraphRAG experiments.

| Dataset | Method | Leak(N) | Leak(E) | Prec(N) | Prec(E) |
|---|---|---:|---:|---:|---:|
| Medical | IKEA | 14.73 | 0.43 | 4.56 | 0.12 |
| Medical | CopyBreakRAG | 50.42 | 12.64 | 14.20 | 2.79 |
| Medical | TGTB | 52.16 | 13.67 | 24.65 | 5.43 |
| Medical | PIDE | 43.43 | 11.53 | 41.00 | 9.18 |
| Medical | AGEA-Naive | 67.81 | 18.85 | 34.47 | 7.69 |
| Agriculture | IKEA | 12.53 | 1.28 | 5.97 | 0.30 |
| Agriculture | CopyBreakRAG | 28.95 | 5.00 | 9.06 | 0.97 |
| Agriculture | TGTB | 45.04 | 13.68 | 26.42 | 6.14 |
| Agriculture | PIDE | 59.75 | 19.06 | 33.19 | 6.42 |
| Agriculture | AGEA-Naive | 62.83 | 22.10 | 30.61 | 7.29 |

Conclusion: Ordinary vector retrieval exposes entities more readily than relationships because edges often require cross-fragment aggregation and graph-structural cues. GraphRAG's structured retrieval improves reasoning while also expanding the attack surface for relational-structure leakage.

## 12. Key Conclusions

| No. | Conclusion | Supporting data or mechanism |
|---:|---|---|
| 1 | GraphRAG is vulnerable to graph-level structural leakage | An attacker recovers entities, relationships, and important nodes through black-box queries alone |
| 2 | AGEA is better suited to GraphRAG than existing RAG extraction attacks | In the main experiments, AGEA is best or nearly best in node leakage, edge leakage, and precision |
| 3 | Edge recovery is the principal bottleneck when older methods transfer to GraphRAG | Baselines often extract nodes but have low edge leakage and edge precision |
| 4 | Adaptive exploration-exploitation is essential to query efficiency | Exploration alone lacks coverage; exploitation alone amplifies local errors |
| 5 | The filtering module protects precision | Removing filtering usually raises apparent leakage slightly but lowers precision substantially |
| 6 | AGEA tends to recover structurally important nodes | Leak(Deg) and Leak(PR) exceed the strongest baseline |
| 7 | Leakage falls on large graphs, but the risk persists | On Novel 20 books, AGEA still reaches 60.71 node leakage and 52.57 edge leakage |

## 13. Limitations

| Limitation | Description | Effect on conclusions |
|---|---|---|
| Dependence on structured output and parsing | AGEA requires system responses to expose enough entity and relationship structure | Extraction reliability may decline if the system enforces prose-only answers or suppresses entity-relationship formats |
| Relatively clean threat model | The paper focuses on a fixed-query-budget black-box setting | It does not fully cover monitoring, rate limits, filtering, and multi-turn detection in real deployments |
| Limited system coverage | Experiments cover M-GraphRAG and LightRAG | Different graph construction, retrieval strategies, and corpus quality may change leakage patterns |
| Attribute leakage is underexplored | The main evaluation focuses on nodes and edges | Leakage of node descriptions, attributes, and community summaries needs further measurement |
| Limited attack-defense dynamics | The paper does not fully simulate defense-aware attacks | Actual success rates under stronger defenses may differ |

---

## 14. Defensive Implications

GraphRAG defenses must address more than “do not repeat the source text.” They must also prevent entities, relationships, and neighborhood structure from leaking progressively through multi-turn interaction.

| Defense direction | Targeted risk | Description |
|---|---|---|
| Retrieval-stage filtering | Reduce the probability that sensitive entities and relationships enter context | Apply access control to sensitive nodes, edges, and attributes |
| Response sanitization | Reduce explicit entity-relationship structure in answers | Avoid complete relationship lists, neighbor lists, or internal retrieval structure |
| Structured-output restrictions | Lower rule-based parsing efficiency | Rewrite or reject requests for entity-relationship formatting |
| Query rewriting | Reduce malicious control over graph traversal | Rewrite highly enumerative or traversal-oriented queries into ordinary summary requests |
| Multi-turn traversal monitoring | Detect systematic graph exploration | Monitor whether a user repeatedly asks about node neighborhoods, hubs, or relationship types |
| Rate limiting | Raise the cost of long-term reconstruction | Limit highly structured queries per unit time |
| Anomalous graph-coverage detection | Detect query sequences that continually expand graph coverage | Track entity sets, edge sets, and novelty trends reached by one user's queries |
| Privacy-aware GraphRAG design | Reduce structural leakage at the architecture level | Introduce permissions, least-necessary context, differential privacy, or access policies |
