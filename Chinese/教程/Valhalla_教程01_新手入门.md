# Valhalla 教程01

> 适合对象：第一次接触 Valhalla的用户  
>
> 学习目标：用自然语言完成一次“建立知识库 → 使用知识推进项目”的完整流程  
>
> 预计时间：30～40 分钟

## 1. 理解 Valhalla

Valhalla 是一个由 Codex 操作的本地研究知识库和项目工作环境。

valhalla 参考了数据库的总体架构，分为知识库系统和知识库操作系统。

知识库系统用来存储知识，而知识库操作系统用来管理和使用知识库系统中的知识。

Valhalla 不只是“存文件”，它还可以通过codex等agent利用知识库系统中的知识回答问题、比较方案、设计实验、协助写论文和推进代码任务。

## 2. 新手不需要学习什么

刚开始使用时，你不需要：

- 知道valhalla的系统架构。
- 知道 Router、Contract、Workflow 等valhalla的内部工作机制。
- 手动修改系统文件，以满足你的定制要求。
- 学习 Python 命令。

你只需要在 Codex 对话中说明目标。

尽管实践中发现，只要第一次激活valhalla，即输入`$valhalla`显式触发skill，就可以一直使用该系统，但也可以每次请求都以 `$valhalla` 开头，让系统明确知道你要使用 Valhalla。

例如：

```text
$valhalla 当前状态
```

## 3. 使用前要认识的三个词

### 3.1 Root

Root 是整个 Valhalla 工作环境的总文件夹，其中包含资料、知识库和系统记录。

一个Root文件夹，就是一个完整的`知识库系统`。

一台电脑可以登记多个 root，但同一时刻只会使用其中一个。

### 3.2 知识库

`知识库`是知识库系统的核心概念：

一个知识库系统中的资料可能用于多个项目或者研究方向，因此必须将其中的知识组织起来，一个知识库就是对应的项目的知识支撑。

### 3.3 状态

Valhalla 有两组容易混淆的状态。

**系统状态**：

- `base`：普通状态，用于日常查询和项目工作。
- `admin`：管理状态，用于 root 管理、检查、黑名单等维护任务。

这个状态是为了防止一些非常重要的命令被随意触发。

**会话状态**：

- `idle`：当前没有启动知识库。
- `kb:<名称>`：某个知识库已经启动。

构建、管理、使用知识库时必须有目标，必须有会话状态来选定目标知识库。

新手日常使用时，最常见的状态是 `base + kb:<名称>`。

## 4. 安装Valhalla

尽管提供的Valhalla安装包已经是一个完整的skill了，但由于Valhalla不是一般的skill，它更像是一个以skill为载体的AI操作系统，它太大了，因此不建议直接放到codex的skill中，这样不会自动成为codex的skill。

标准方法是启动codex的`skill creator`安装。

只需输入

```text
$skill-creator 将<valhalla包的路径>安装成skill
```

即可安装完毕

## 5. 第一次使用：完成最小知识库系统的构建

下面的命令可以逐条发送，不要一次全部发送。

### 第一步：启动valhalla并初始化系统

输入：

```text
$valhalla
```

这将启动valhalla系统，如果这是本次会话第一次启动，则将会启动一次自检，验证系统完整性。

### 第二步：查看当前状态

```text
当前状态
```

重点查看系统回复中的三项内容：

1. 当前 root 是否存在。
2. 系统状态是否为 `base`。
3. 当前是否已经启动知识库。

如果系统提示缺少 root，不要自行修改文件，直接说：

```text
请解释当前缺少什么，以及下一步应该怎么做。先不要修改任何文件。
```

### 第三步：创建Root

原始资料十分宝贵，是一切知识库的基础，而Valhalla作为一个AIOS，可能会有一些不确定的后果，因此Valhalla没有改动原始资料的操作，以防止原始资料被不受控制的修改。

创建root步骤如下：

1. 在需要的位置新建一个文件夹，将其进行命名。这个文件夹就是Valhalla的root文件夹。
2. 进入Valhalla的管理状态，输入`进入管理状态`或`进入admin`。因为root操作是一个极度重要的操作，因此必须处于admin状态，防止被误触发。
3. 创建root，输入`创建root，<root文件夹的路径>`，可以给该root加上别名，如输入`创建root，<root文件夹的路径>，<该root的别名>`,即可完成root创建。
4. 可以再次查看当前状态，如果当前root不是目标root，可以输入`列出所有root`获得本机的所有root，输入`切换root，<目标root的别名>`完成root的切换和启动。

### 第四步：新建知识库

确定了root，就确定了当前操作的知识库系统。下一步就是在该知识库系统中构建知识库

新建知识库,输入

```text
建立知识库 <知识库名>
```

关于知识库，还可以在这里尝试一些其他操作。

查看当前知识库：

```text
$valhalla 当前知识库
```

如果你不知道有哪些知识库，可以要求系统列出当前 root 中可用的知识库：

```text
$valhalla 请列出已有的知识库。
```

经过前四步，已经建立起了一个知识库系统，以及该知识库系统中的一个空知识库。

### 第五步：启动一个知识库

现在开始尝试管理这个空知识库，首先要启动目标知识库：

```text
$valhalla 启动知识库 <知识库名>
```

成功后，会话状态应变为：

```text
kb:药物设计
```

可以通过输入`当前状态`或`知识库状态`查看。

“启动知识库”不是打开一个文件夹，而是告诉系统：后续操作默认针对这个知识库。

### 第六步：摄入资料，充实知识库

`摄入`是Valhalla中的一个相当复杂的指令，也是Valhalla的一个核心指令，在这里不会解释这个指令的运行逻辑，只介绍这个指令能做什么。

对于资料文件集合，直接用它们去推进项目或者研究是十分奇怪的`文件推进项目`逻辑，正常的逻辑应该是`知识推进项目`。

需要从文件中提取知识,然后再利用这些知识推进项目。

`摄入`就是这个从文件中提取知识的过程。

以下是`摄入`操作的标准流程：

1. 准备文件。

   在当前root下有一个Library文件夹，这里就是存放原始资料的地方。如前所述，为了安全起见，这个地方不提供指令进行操作，请手动操作。

   这个Library内有一个特殊的文件夹`public_resources`，这是一个特别的文件夹，用于系统存放公共文件备份，使用者不要改动这个文件夹里的任何东西。

   可以在Library文件夹里按照使用者意愿组织并存放资料，当然，不要动`public_resources`。

2. 确定目标知识库

   输入`当前状态`或`知识库状态`查看是否是需要的目标知识库。

   这一步不是必须的，但最好是这么做，因为暂时valhalla还没有可靠的回滚机制，当然可以通过修改指令的工作流实现回滚，但目前基础版的Valhalla并没有实现这项功能。

   起步阶段，初学者最好谨慎一点。

3. 摄入文件。

   选取Library中要摄入的文件，复制其路径。

   输入命令`摄入<文件路径>`即可完成摄入操作。

4. 查看摄入成果

   输入命令`列出知识点`或者`所有entity`即可查看该知识库中的所有从原始资料中摄入到的知识点。

### 第七步 更高层级的知识结构的构筑(可选)

1. 构筑关系

   知识点并非孤立存在的，它们之间存在联系，这些联系也是知识的一种。

   输入`总结知识点之间的关系`，就可以构筑本知识库中所有知识点之间的关系。

   可以输入`查看关系`，`查看<关系类型>关系`查看有哪些关系。

2. 构筑知识图谱

   知识点之间的关系以及可以构筑知识图谱，但这里构筑的关系是多种多样的，可以根据需要构筑不同的图谱。

   输入`根据<关系类型>构筑知识图谱`，就可以根据要求，构筑对应关系的知识图谱。

### 第八步 使用知识库进行查询

查询操作实际上是一个默认操作，并不需要特意输入`查询`,但如果加上则更稳定。

```text
$valhalla 查询 当前知识库主要包含哪些研究主题？请按主题列出，并说明信息来源。
```

更好的提问通常包含：

- 想了解什么。
- 希望用表格、提纲还是短文回答。
- 是否要求列出来源。
- 知识库证据不足时是否允许联网。

示例：

```text
$valhalla 查询
问题：当前知识库中有哪些分子生成方法？
输出：用表格比较方法、输入、输出、优势和限制。
来源：只使用当前知识库，并列出依据。
证据不足时：明确告诉我，不要自动联网。
```

### 第九步 摄入对话

`摄入对话`是一个特殊的摄入操作。

使用查询操作和Valhalla针对知识库中的知识进行研讨，这些研讨也是知识的一种，这些知识不该被丢弃。

摄入本轮会话中的知识点并存储，这样才能做到知识的积淀。

对话完成后，输入`摄入对话`，即可摄入本轮会话的知识点。

提示：摄入对话的知识点和摄入Library中的文件的知识点，是两种不同的类型。

### 第十步：用知识库推进一个任务

查询用于“了解知识”，项目推进用于“产出成果”。

```text
$valhalla 基于当前知识库推进：
目标：设计一份比较模型 A 和模型 B 的实验方案。
输出：研究假设、变量、数据、步骤、评价指标、风险和成功判据。
要求：标出知识库依据和仍需补充的信息。
```

项目推进结果默认只出现在回复中，不会自动写回知识库。

### 第十一步：摄入工程经验

`摄入工程经验`是一个特殊的摄入操作。

工程经验也是知识的一种，这些知识不该被丢弃。

摄入工程中的知识点并存储，做到知识的积淀。

工程完成后，输入`摄入工程经验`，即可摄入本轮项目推进的知识点。

提示：摄入工程经验的知识点，和摄入对话的知识点以及摄入Library中的文件的知识点，是不同的类型。这样就有三大类的知识点

### 第十二步：退出知识库

```text
$valhalla 退出知识库
```

退出后，会话状态回到 `idle`。

至此，你已经完成了第一次 Valhalla 使用闭环。
