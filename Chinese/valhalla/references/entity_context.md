## 1. 核心定义

AGEA，即 Agentic Graph Extraction Attack，是一种面向 GraphRAG 系统的查询高效智能体式图抽取攻击方法。它在黑盒、固定查询预算的条件下，通过多轮自适应查询，从 GraphRAG 的自然语言响应中恢复隐藏知识图谱中的实体、关系和局部结构。

该实体描述的不是单个提示词或单个实验，而是论文提出的完整主题：GraphRAG 图级抽取风险、AGEA 方法框架、查询策略、抽取过滤机制、实验验证、局限性与防御启示。

### 核心要点速览

| 维度 | 内容 |
|---|---|
| 研究对象 | GraphRAG 系统中的隐藏实体-关系图泄漏风险 |
| 攻击目标 | 在固定查询预算内恢复内部知识图谱的节点、边和结构化关系 |
| 威胁模型 | 黑盒访问；攻击者只能提交查询并观察系统回答 |
| 方法名称 | Agentic Graph Extraction Attack，简称 AGEA |
| 方法核心 | 查询生成、图抽取过滤、图记忆、查询记忆、新颖度驱动探索-利用 |
| 主要优势 | 在相同查询预算下比既有 RAG 抽取攻击恢复更多节点和边，并保持较高精度 |
| 最大风险 | GraphRAG 不只可能泄露文本，还可能泄露可复用、可查询的关系图结构 |
| 防御方向 | 响应净化、结构化输出限制、遍历行为监控、查询改写、速率限制、隐私感知 GraphRAG 设计 |

## 2. 问题背景

GraphRAG 将文档集合组织成由实体和关系构成的图，再围绕用户查询检索相关子图并生成回答。相比普通 RAG 的文本块检索，GraphRAG 暴露的是更结构化的攻击面：攻击者可以通过多轮查询遍历图、扩展邻域并拼接关系证据，从而恢复可复用的关系图结构。

该风险的关键不只是泄露原文片段，而是泄露“谁与谁有关、通过什么关系相连、哪些节点是核心枢纽”等结构化知识。对医疗、组织关系、通信关系或业务知识图谱而言，这类泄露可能支持后续的关联推断和定向分析。

### GraphRAG 与普通 RAG 的风险差异

| 对比维度 | 普通 RAG 抽取风险 | GraphRAG 图级抽取风险 |
|---|---|---|
| 主要资产 | 文本块、文档片段、检索上下文 | 实体、关系、子图、图结构 |
| 泄漏单位 | 句子、段落、chunk、document | 节点、边、路径、邻域、社区 |
| 攻击收益 | 获得部分原文或事实 | 获得可复用、可查询的结构化知识图 |
| 多轮风险 | 重复检索更多文本块 | 沿图遍历、扩展邻域、恢复图骨架 |
| 后续危害 | 内容泄漏、版权或隐私问题 | 关联推断、组织结构还原、敏感关系发现 |

## 3. 威胁模型

论文研究的是预算受限的黑盒设置。攻击者不能访问 GraphRAG 的检索器、内部知识图谱、被检索子图或底层模型参数，只能提交查询并观察系统返回的自然语言响应。

攻击目标是在尽量少的查询次数内恢复 GraphRAG 内部图中的实体集合和关系集合。难点包括：响应文本可能混合真实检索内容、模型生成背景和幻觉关系；攻击者看不到真实检索子图；有限查询预算下，朴素重复查询容易浪费在低收益或已饱和区域。

### 威胁模型表

| 项目 | 设定 |
|---|---|
| 攻击者访问权限 | 只能通过查询接口与 GraphRAG 交互 |
| 攻击者不可见内容 | 内部知识图谱、检索器、被检索子图、底层模型参数 |
| 攻击者可见内容 | 用户查询对应的自然语言回答 |
| 攻击目标 | 恢复实体集合、关系集合和部分图结构 |
| 预算约束 | 固定查询次数，主实验为 1000 次查询 |
| 评估对象 | 被抽取图与真实内部图之间的覆盖率和正确性 |
| 主要挑战 | 响应噪声、幻觉关系、查询冗余、局部饱和、长程规划 |

## 4. 方法总览

AGEA 将图抽取建模为一个闭环反馈过程，包含四类核心组件：

| 组件 | 中文说明 | 在 AGEA 中的作用 |
|---|---|---|
| Query Generator Q | 自适应攻击查询生成器 | 根据当前图状态、历史查询和新颖度反馈生成下一轮查询 |
| Graph Extraction-Filter Module F | 图抽取-过滤模块 | 从回答中抽取候选实体关系，并过滤泛化项、重复项、无依据关系和幻觉节点 |
| Graph Memory M_G | 图记忆 | 同时维护原始候选图和过滤后的高置信图 |
| Query Memory M_Q | 查询记忆 | 记录历史查询、响应摘要、抽取结果、模式选择和新颖度趋势 |

AGEA 的关键思想是把“发现更多图结构”和“保持抽取精度”分开处理：先快速发现候选实体关系以计算新颖度，再用过滤模块控制噪声，最后把可信结果写入过滤图。

### 方法流程

| 步骤 | 输入 | 处理 | 输出 |
|---:|---|---|---|
| 1 | 已抽取图、查询记忆、新颖度趋势 | 选择探索或利用模式 | 查询模式 |
| 2 | 查询模式、过滤图、近期历史 | 生成自然语言查询 | 攻击查询 |
| 3 | 攻击查询 | 目标 GraphRAG 检索子图并生成回答 | 自然语言响应 |
| 4 | 响应文本 | 发现阶段解析候选实体与关系 | 原始候选图更新 |
| 5 | 候选实体关系、响应证据、过滤图上下文 | 过滤阶段验证并去噪 | 高置信实体关系 |
| 6 | 原始图、过滤图、查询记忆 | 计算新颖度并更新状态 | 下一轮查询依据 |

## 5. 算法机制

### 5.1 两阶段图知识抽取

AGEA 使用两阶段抽取流程。第一阶段是发现阶段，目标是快速从响应中得到候选实体和候选关系，用来更新原始图并计算新颖度。第二阶段是过滤阶段，目标是把泛化实体、重复表达、无依据边和异常密集连接从候选结果中移除，只把高置信实体与关系写入最终过滤图。

| 阶段 | 目标 | 方法 | 优点 | 风险或不足 |
|---|---|---|---|---|
| 发现阶段 | 快速获得候选实体和关系 | 结构化输出诱导 + 规则解析 + 规范化 + 去重 | 开销低，能每轮计算新颖度 | 容易包含泛化项、幻觉关系或格式噪声 |
| 过滤阶段 | 保留高置信图结构 | 使用 LLM 过滤代理结合响应证据和图记忆判断 | 提高精度，减少错误边扩散 | 会带来额外推理开销，并依赖模型判断质量 |

### 5.2 图记忆

AGEA 同时维护两个图状态：

| 图状态 | 内容 | 主要用途 |
|---|---|---|
| 原始图 G_r | 发现阶段得到的所有候选实体和候选关系 | 计算新颖度，判断当前查询是否仍有发现价值 |
| 过滤图 G_f | 经过过滤确认的高置信实体和关系 | 最终评估、查询规划、重复检测、选择可利用的高价值节点 |

这种双图设计避免了过早过滤导致新颖度被低估，也避免了直接把噪声写入最终图。原始图偏向召回，过滤图偏向精度；两者共同服务于查询效率。

### 5.3 查询记忆

查询记忆记录近期查询、响应摘要、抽取结果、模式选择和新颖度趋势。它的作用是避免重复探索同一区域，并让查询生成器根据历史反馈选择更有潜力的查询方向。

| 记忆内容 | 用途 |
|---|---|
| 历史查询 | 避免重复问相似问题 |
| 响应摘要 | 判断哪些主题已被覆盖 |
| 近期抽取实体 | 避免马上重复探索同一批实体 |
| 新颖度分数 | 判断当前区域是否饱和 |
| 模式选择记录 | 分析探索与利用是否失衡 |
| 实体查询频次 | 防止过度围绕单个 hub 反复查询 |

### 5.4 新颖度驱动的探索-利用策略

AGEA 在探索和利用之间切换。探索模式用于发现新的实体类型、关系类型和图区域；利用模式则围绕已发现的高价值实体扩展局部邻域。

论文将新颖度解释为“饱和信号”。当近期新颖度低时，说明当前查询多在重复已知节点或边，应转向探索；当近期新颖度高时，说明当前区域仍有抽取价值，可以围绕已有实体继续利用。过滤图还用于识别高连接实体，从而指导利用阶段选择更可能产生新边的节点。

| 模式 | 目标 | 触发倾向 | 查询特点 | 可能问题 |
|---|---|---|---|---|
| Explore | 发现新的实体、关系类型和图区域 | 近期新颖度低或随机探索触发 | 主题更广、覆盖更大、避免近期实体 | 可能命中率低，难以深入关系 |
| Exploit | 围绕已有实体扩展邻域 | 近期新颖度高，说明当前区域仍有价值 | 聚焦 hub 或新发现实体，追问直接关系 | 可能放大局部错误或陷入局部图区域 |

### 5.5 关键超参数

| 参数 | 论文设置 | 含义 |
|---|---:|---|
| 初始探索概率 ε_init | 0.3 | 攻击早期保持较高探索比例 |
| 最小探索概率 ε_min | 0.05 | 攻击后期仍保留少量随机探索 |
| 探索概率衰减 | 0.98 / turn | 随查询轮次逐步从探索转向利用 |
| 初始新颖度阈值 τ_init | 0.15 | 判断近期查询是否饱和的初始阈值 |
| 近期窗口 k | 5 | 用最近 5 轮平均新颖度辅助模式选择 |
| 主实验查询预算 | 1000 | Medical 与 Agriculture 主实验预算 |

## 7. 主实验结果

主实验最重要的结论是：AGEA 在两个 GraphRAG 系统和两个主要领域数据集上，都取得最高或接近最高的节点/边泄漏率，并且精度明显高于大多数基线。尤其是边恢复能力，AGEA 相比既有方法提升更明显。

### 7.1 AGEA 最终表现汇总

| 系统 | 数据集 | Leak(N) | Leak(E) | Prec(N) | Prec(E) |
|---|---|---:|---:|---:|---:|
| M-GraphRAG | Medical | 87.09 | 80.16 | 87.09 | 61.18 |
| M-GraphRAG | Agriculture | 84.67 | 84.13 | 93.08 | 76.81 |
| LightRAG | Medical | 96.42 | 95.90 | 98.34 | 97.97 |
| LightRAG | Agriculture | 88.05 | 87.11 | 98.11 | 96.65 |

### 7.2 相比最强基线的提升

| 系统 | 数据集 | 节点泄漏提升 | 边泄漏提升 | 节点精度提升 | 边精度提升 |

从这个对比可以看出，AGEA 的主要优势不只是“多抽到实体”，而是显著提高关系恢复能力。旧有 RAG 抽取攻击迁移到 GraphRAG 时，常见瓶颈是能抽出节点，但抽不准边；AGEA 通过查询规划和过滤机制缩小了节点抽取与边抽取之间的差距。

## 11. 补充实验：Naive-RAG 对照

论文还在一个普通向量检索式 Naive-RAG 设置上进行了补充实验，用于区分“GraphRAG 图结构检索面”与“普通文本检索面”的差异。结果显示，去掉图结构后，所有方法的边恢复能力明显下降；AGEA-Naive 仍能获得最高节点和边泄漏率，但精度远低于 GraphRAG 主实验设置。

## 12. 关键结论

| 编号 | 结论 | 数据或机制支撑 |
|---:|---|---|
| 1 | GraphRAG 存在图级结构泄漏风险 | 攻击者仅通过黑盒查询即可恢复实体、关系和重要节点 |
| 2 | AGEA 相比既有 RAG 抽取攻击更适合 GraphRAG | 主实验中 AGEA 在节点、边、精度上均优于或接近最优 |
| 3 | 边恢复是旧方法迁移到 GraphRAG 的主要瓶颈 | 基线方法常能抽出节点，但边泄漏和边精度较低 |
| 4 | 自适应探索-利用是查询效率的关键 | 只探索覆盖不足，只利用会放大局部错误 |
| 5 | 过滤模块是精度保护模块 | 去掉过滤通常使表面泄漏略升，但精度明显下降 |
| 6 | AGEA 倾向恢复结构重要节点 | Leak(Deg) 与 Leak(PR) 高于最强基线 |
| 7 | 大图上泄漏率下降但风险仍然存在 | Novel 20 books 中 AGEA 仍恢复 60.71 节点泄漏和 52.57 边泄漏 |

## 13. 局限性

| 局限 | 说明 | 对结论的影响 |
|---|---|---|
| 依赖结构化输出和解析 | AGEA 依赖系统响应中暴露足够实体和关系结构 | 如果系统强制段落式回答或抑制实体-关系格式，抽取可靠性可能下降 |
| 威胁模型较干净 | 论文主要研究固定查询预算下的黑盒设置 | 未完整覆盖真实部署中的监控、限流、过滤和多轮检测 |
| 系统覆盖有限 | 实验覆盖 M-GraphRAG 和 LightRAG | 不同图构建、检索策略和语料质量可能改变泄漏模式 |
| 属性泄漏未充分展开 | 主体评估聚焦节点和边 | 节点描述、属性、社区摘要等泄漏仍需进一步衡量 |
| 攻防动态不足 | 论文没有完整模拟防御感知攻击 | 更强防御下的实际成功率可能不同 |

## 14. 防御启示

GraphRAG 防御不能只关注“不要原文复述”，还必须关注“不要在多轮交互中逐步泄漏实体、关系和邻域结构”。

| 防御方向 | 目标风险 | 说明 |
|---|---|---|
| 检索阶段过滤 | 降低敏感实体和关系进入上下文的概率 | 对敏感节点、边或属性实施访问控制 |
| 响应净化 | 减少回答中显式暴露实体-关系结构 | 避免输出完整关系清单、邻居列表或内部检索结构 |
| 结构化输出限制 | 降低规则解析效率 | 对实体-关系格式化请求进行改写或拒绝 |
| 查询改写 | 降低恶意查询对图遍历的控制力 | 将过于枚举式、遍历式的查询改写为普通摘要式回答 |
| 多轮遍历监控 | 发现系统性图探索行为 | 监控用户是否围绕节点邻域、hub、关系类型反复追问 |
| 速率限制 | 提高长期重构成本 | 限制单位时间内的高结构化查询数量 |
| 异常图覆盖检测 | 发现持续扩展图覆盖面的查询序列 | 统计单用户查询命中的实体集合、边集合和新颖度趋势 |
| 隐私感知 GraphRAG 设计 | 从架构层降低图结构泄漏 | 引入权限、最小必要上下文、差分隐私或访问策略 |
